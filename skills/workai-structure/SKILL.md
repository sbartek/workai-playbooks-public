# workai structure

`~/workai` is the workspace for all of the user's projects.

## Top level

```
~/workai/
  CLAUDE.md      the index: one line per hub, generated by report.py --index
  projects/      active projects
  archives/      inactive projects (finished, paused, dropped)
```

There are only these two folders. Whether a project is active is the only
question that decides where it lives.

## Project hubs

A project is a **hub**: a folder named `NN-name`, its own private git repo.

```
projects/01-workai-playbooks/
  README.md        goal, decisions, status
  CLAUDE.md        how agents work on this project
  STRUCTURE        structure version this hub follows, e.g. 1.0.0
  backlog/         cards: todo/ doing/ done/ archive/, and parked/ once a card
                   is parked (see workai-backlog skill)
  notes/           research and findings
  repos/           outcome repos, each its own git repo; ignored by the hub's git
  worktrees/       per-card git worktrees; ignored by the hub's git
```

- **The hub holds the work about the project**: plans, decisions, backlog,
  notes, agent instructions.
- **`repos/` holds the outcomes**: code, packages, sites, anything shared or
  installed elsewhere. Hub material never goes into an outcome repo.
- Each repo in `repos/` is a clean main checkout. Changes happen in
  `worktrees/<repo>/<NNN-slug>/` on branch `card/<NNN-slug>`, one per backlog
  card.
- Code in one project that another project uses is referenced through git
  (a dependency on its GitHub repo) or through an installed location, never by
  a relative path into another hub: hubs move between `projects/` and
  `archives/`.

## Numbering

| Thing | Form | Said as |
|---|---|---|
| Project | 2 digits, `01` | "project 1" |
| Card | 3 digits, `009` | "card 9" |
| Card in another project | `01-009` | "card 9 in project 1" |
| Old-style project | `L38` | "L38" or its name |

- Project numbers are consecutive across `projects/` and `archives/` together.
  The next project gets the highest existing number plus one. Numbers are
  never reused.
- "project N" and a bare number always mean the hub numbered N.
- Old-style projects keep their old number with an `L` prefix: `L38` is Ceramics.
  `L30` and `L31` were each used twice, so name the project when citing them.
  A migrated project gets a new number; its `L` number is then history.
- The project number is read from the folder name only. It is not repeated
  inside files, so a renumbered or moved hub is never out of step.

## Old-style projects

Many folders in `projects/` predate hubs: a plain repo or a standalone `.md`
plan, unnumbered. They count as structure version 0. They are migrated one at
a time, only when the user asks, never as a side effect of other work.

## Structure versions

The structure is versioned by the releases of the `workai-playbooks` repo
(`a.b.c`). The major number `a` is the structure version: same major, same
structure. Each hub's `STRUCTURE` file records the version it follows. A hub
whose major is lower than the current release needs migrating; the steps are in
the Migration sections of `CHANGELOG.md` in `workai-playbooks`.

## Git and concurrency

Several agents work in the same hubs at once. These rules keep their work
visible to each other and the history intact. The backlog, new-project and
migrate skills follow them.

**Claims and hub edits**
- A card is claimed by `mv backlog/todo/X backlog/doing/` in the hub's
  **main checkout** (the shared folder), then committed at once. A claim
  made in a hub worktree or branch is invisible to the others and does not
  count.
- Commit hub changes straight away and only your own paths:
  `git -C <hub> commit -m "..." -- <path> <path>`. Never `git add -A` or
  `commit -a` in a hub another agent may be editing.
- If a session cannot write the main checkout, edit in a temporary hub
  worktree, then rebase it on the hub's main and `merge --ff-only` from the
  main checkout; remove the worktree and branch. The claim (the `mv`) still
  happens on main.

**Ids and numbers**
- Card ids and hub numbers are allocated only on the hub's main (the
  workai root for hub numbers), under the shared-file lock
  (workai-migrate skill, `lock.sh`), and committed before the lock is
  released. A draft card written elsewhere is named `draft-<slug>.md` and
  gets its id when it lands on main.
- When a main agent hands id ranges to parallel agents, it writes the
  ranges into the hub (a card's Notes), and each agent still takes the lock.
- `scripts/check-skills.py --cards` (and `report.py`, as a warning) reject
  two cards with the same id in one hub.

**History**
- Never `commit --amend`, `rebase`, `reset` or force-push on a shared main
  (a hub, the workai root, a repo's main). Only your own unmerged card
  branch may be rewritten.
- A repo's main moves only by `git merge --ff-only card/NNN-slug`, after
  rebasing the branch on the latest main and rerunning every test. One
  exception, `workai-playbooks` (AI reviewer pilot, card 01-084): main moves
  only through a reviewed pull request, `gh pr merge --rebase`, which also
  keeps it linear (workai-backlog skill, finishing a Repo card).

**What an agent may commit without asking**
- Hub repos: claims, card files, notes, README/CLAUDE.md of the hub it works
  in (as above).
- Outcome repos: card branches, and main through the ff-merge above (for
  workai-playbooks, the PR rebase-merge above).
- The workai root (`~/workai`), under the lock, only: pruning stale lines
  from `next.md`; a Next list the user approved; the generated index
  `CLAUDE.md` (`report.py --index`, never hand-edited) and the `.gitignore`
  lines that new-project, migrate and archive write. Anything else in the
  root: ask.

**What an agent may push without asking** (decided by the user 2026-10-25,
card 01-108)
- **Private hubs, the private workai root and private outcome repos: push
  after each finished card**, as an off-machine backup. Every repo has the
  scanning pre-push hook (card 01-141), which stops a push with secrets or
  identity documents; never `--no-verify`.
- A new or migrated hub's first push: through `push-hub.sh` (scans, then
  `gh repo create --private`).
- **Ask first** for: public repos (any repo `gh repo view --json visibility`
  calls PUBLIC); a push that deploys (a repo whose main runs a Deploy
  workflow: the user pushes it); anything that rewrites remote history; a
  local-only hub (one with no remote on purpose).
- Pushing never replaces finishing: the card is done (Done-when checked,
  Notes written) before its commits go out.

**Remotes**
- Every hub and outcome repo has a private remote, or its hub README says
  why not (e.g. a hub kept local only by the user's choice, with its
  backup as a git bundle on another disk, described in its README).

## Global rules (`~/.claude/CLAUDE.md`)

The rules every Claude Code session loads live in `~/.claude/CLAUDE.md`, a
plain file owned by each machine's user: edit it there, never in a repo.
workai-playbooks ships only a generic `claude/CLAUDE.md.template`, which
`install.sh claude` copies there when the file is missing and never
otherwise (card 01-155; the link of card 01-152 is migrated to a plain file
with the same content). Personal rules do not go into the repo. No
identifiers in the file (ID, account or phone numbers, addresses, other
people's details).

## Rules for agents

- Never move, rename or renumber a project without the user's confirmation.
  Moving breaks every reference to the old path (launchd jobs, crontab,
  `~/workai/CLAUDE.md`, `.gitignore`, memory notes, installed symlinks); find
  and update all of them, then check that each still works.
- A new project gets a hub with the layout above and its folder is added to
  `~/workai/.gitignore`.
- `~/workai/CLAUDE.md` is generated by `report.py --index`, one line per hub
  from its README (title, old `Lnn`, first Goal sentence or its
  `<!-- index: ... -->` line): never edit it by hand. new-project.sh,
  migrate.sh and archive.sh regenerate and commit it under the lock
  (`regen-index.sh`, workai-open-project skill); after changing a hub's
  title or goal, run `regen-index.sh` yourself.
- A hub's README may carry `<!-- aliases: word, word -->`: extra names it
  is opened by (workai-open-project), for words in neither its folder name,
  title nor `repos/` folder names (those match already). Lookup only: it
  never reaches the index or `--list`. When hubs merge, the archived one's
  title ends `(merged into NN — Name)`, so a name both match opens NN.
- When working in a hub, read its `README.md` and `CLAUDE.md` first.
- Use absolute paths (`<hub>/backlog/...`, `git -C <hub> ...`), one command
  per call: never `cd X && ...` or `;` chains. These skills must work for
  any agent (Claude Code, opencode), and some agents' shells set the folder
  per call instead of a `cd`.
- When a skill says ask the user (or wait for a yes) and the agent has no way
  to ask (a headless run, no question tool), end with the question as plain
  text and stop. Never take silence as a yes or answer the question yourself.
